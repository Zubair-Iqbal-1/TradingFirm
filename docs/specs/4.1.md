**Doc lines quoted in this spec (OpenRouter, fetched 2026-09-20):**

- Structured output request shape: "include a `response_format` parameter in your request, with `type` set to `json_schema` and the `json_schema` object containing your schema" — with `name`, `strict`, `schema` inside it (`docs/features/structured-outputs`).
- Strict-mode caveat, quoted because it is why this part still validates the answer itself: "Set `strict: true` so that providers with a native strict mode enforce your schema exactly. Enforcement varies by provider: some guarantee schema-conforming output, while others translate your schema into their own structured-output format or treat it as a strong hint, **so exact compliance is not guaranteed on every endpoint**." (`docs/features/structured-outputs.md`, line 133).
- Reasoning request field: a top-level `reasoning` object; `"effort"` takes `"max" | "xhigh" | "high" | "medium" | "low" | "minimal" | "none"` (`docs/use-cases/reasoning-tokens.md`, line 76).
- Per-model reasoning metadata: "Each model in `GET /api/v1/models` may include a `reasoning` object describing which effort levels it accepts and whether reasoning is mandatory"; "**`supported_efforts`**: Filter effort selectors to these values"; "**`mandatory`**: When `true`, hide disable controls and do not send `effort: "none"` — the model rejects it." (same file, lines 110–130).
- Anthropic + reasoning: "You can enable reasoning on Anthropic models **only** using the unified `reasoning` parameter with either `effort` or `max_tokens`"; and "For Anthropic models, `max_tokens` must be strictly higher than the reasoning budget" (same file, lines 106 / 145).
- Effort → budget: `"low"` "Allocates a smaller portion of tokens for reasoning (approximately 20% of max_tokens)" (same file, line 174). At `llm_max_tokens = 8000` that is ~1,600 for reasoning and ~6,400 for the JSON answer.
- **HTTP 200 with an error body** (fix J, verified): "Otherwise, the returned HTTP response status will be `200` and any error occurred while the LLM is producing the output will be emitted in the response body or as an SSE data event"; "A streaming request receives an SSE error event; **a non-streaming request receives an error body**"; "OpenRouter sends you the HTTP `200 OK` status and headers as soon as the provider accepts the request… **the status stays `200` even when every provider fails — the last error reaches you in the response body**." The body shape is `{"error": {"code": number, "message": string, "metadata"?: object}}`. (`docs/api-reference/errors.md`, lines 100 / 295 / 306 / 85–92.)
- **The `length` shape**, quoted because it is why `finish_reason` is checked before parsing: "A reasoning model spent the whole `max_tokens` budget on reasoning. The response is a `200` with `finish_reason: "length"`, empty `content`, and `usage.completion_tokens_details.reasoning_tokens` close to `usage.completion_tokens`. Retrying does not help" (same file, line 269).
- **408 is a documented status**: "`408`: Your request timed out", alongside `400`, `401`, `402` ("insufficient credits"), `403`, `429`, `502`, `503` (same file, error-codes list). That is fix F: 408 is a wait, not a request we got wrong.
- `Retry-After`: "On `429` and `503` responses, and on `402` responses whose `error.metadata.limit_source` is `openrouter_in_flight_budget`… OpenRouter may include a standard HTTP `Retry-After` response header indicating how many seconds to wait" (same file).
- App-attribution headers: "`HTTP-Referer`: Identifies your app on openrouter.ai"; "`X-OpenRouter-Title`: Sets/modifies your app's title (`X-Title` also accepted)" (`docs/api-reference/overview.md`, lines 196–197).
- Privacy: "On your account settings page, you can set whether you would like to allow routing to providers that may train on your data… If you opt out of training in your account settings, OpenRouter will not route to providers that train." (`docs/features/privacy-and-logging.md`, line 71), settings page `https://openrouter.ai/settings/privacy`. **This is a one-time account setting done by hand — no code in this part reads or sets it.** Note the trade-off: opting out removes training providers from the routing pool for a model, which can change which endpoint serves a model and what it costs.

## Spec

Part 4.1 gives `services/ai-agent` its configuration and one LLM provider: `providers/base.py` defines `LLMProvider.complete_structured(system, user, schema)` plus the typed errors every later part catches, and `providers/openai_compat_provider.py` implements it with the `openai` SDK pointed at **OpenRouter** through a configurable `base_url`, using `response_format` JSON-schema structured output, a per-model reasoning-effort table and one usage log line per call that includes OpenRouter's reported `cost`. A daily call cap and a post-refusal cooldown live in Redis under `tf:ai:` and are checked **before** each request, so a rate limit stops the service instead of starting a retry storm. Nothing in this part calls a live LLM, adds a route, or touches another service.

It must **not**:
- make a live OpenRouter call in any test or during verification, or put a key anywhere but container env (G6, G14)
- add a route, a lifespan, a DB pool, a migration, or a prompt file — `services/ai-agent/main.py` is not edited
- retry a 429, a 5xx, a timeout or a refusal; the SDK's own retries are turned off (`max_retries=0`)
- truncate, repair or re-ask on a response that breaks the caller's schema — it raises
- write into another service's Redis namespace (`tf:cache:` is data-engine's, `tf:risk:` is risk-shield's) or Postgres schema
- change any existing compose service block, any other service's files, or `shared/`
- touch `.env`
- add or edit anything under `.github/`
- rebuild or redeploy prod `ai-agent` (G15 — listed in the report, waiting for a go)

## Writes

| write | before/after success | state left if the op fails after it |
|---|---|---|
| `INCR tf:ai:state:llm_calls:{ET date}`, then `EXPIRE <key> 129600 NX` | **before** the HTTP request (a reservation) | the call counts even if the request then fails — deliberate, see decision 4 |
| `DECR tf:ai:state:llm_calls:{ET date}` | **only** after the over-cap check refuses; no other branch releases | a `DECR` that raises falls through to the in-process counter, which is where the matching `INCR` almost certainly went. In the one case where Redis took the `INCR` and then failed the `DECR`, the Redis key reads **one higher than the number of calls actually made**, so the cap bites one call early — logged WARNING, clears at the next ET midnight |
| `SET tf:ai:cooldown:OPENROUTER "<status>" ex=N` | after a 429 / 401 / 402 / 403, before the error is raised | cooldown stands for N s, and its **value is the status that caused it**, so an out-of-credits hour never reads as a rate limit (fix E). No other state |
| in-process `MemoryCap` counter / `MemoryCooldowns` | whenever the Redis op above is absent or raises | lost on restart (fail-open, decision 4) |
| one INFO log line per completed call | after the response is parsed | n/a — never the prompt, the body or the key |

No Postgres write, no pub/sub publish, nothing in `app.state`.

## Pre-flight order (stated once; every branch below refers to it)

```
1. validate input        → ValueError            (no reservation, no HTTP, no client)
     - system / user non-blank strings
     - label matches ^[A-Za-z0-9_-]{1,64}$   (it becomes json_schema.name)
     - schema is a dict, type == "object", non-empty `required` of non-blank strings
     - effort (if given) is in the model's advertised supported_efforts
2. configured?           → LLMNotConfigured      (no client built)
3. cooldown active?      → LLMCooledDown         (message names the cause)
4. INCR the day counter  (the reservation)
5. over cap?             → DECR, then LLMCapExceeded   ← the only release
6. send
```

Steps 1–3 raise **before** the counter is touched, so nothing to release. Step 5 is the one and only `DECR`. A request that goes out at step 6 counts, whatever it answers.

The `AsyncOpenAI` client is built **lazily, on first use at step 6** (fix A), so "no key → no client built" is literally true and testable: `provider._client is None` after any pre-flight refusal.

| `llm_max_tokens` | `8000` | non-streaming. At `effort: "low"` ~1,600 goes to reasoning and ~6,400 to the answer |
| `llm_timeout` | `150.0` | seconds, hard. risk-shield's `BRIEF_TIMEOUT` is 180 s, so ai-agent must give up first |
| `llm_cooldown_seconds` | `900` | after a 429 with no usable `retry-after`, matching every other source cooldown in the repo |
| `llm_referer` | `""` | `HTTP-Referer`, sent **only** when non-empty. Never a hard-coded value |
| `llm_title` | `""` | `X-Title`, same rule |

Module constants: `LLM_COOLDOWN_MAX = 3600` (the ceiling on any cooldown, including a `retry-after`), `LLM_COOLDOWN_AUTH = 3600` (401 / 402 / 403).

`llm_configured` property = `bool(llm_api_key.get_secret_value())`, the only thing anything reads about the key (G14).

**`LLM_PROVIDER` is not a setting.** One provider in code (D16 amended). The var still exists on the prod `ai-agent` compose block and in `.env`; `model_config = {"extra": "ignore"}` means `Settings` ignores it, so **the prod block is not edited** and the byte-identical proof holds. `ANTHROPIC_API_KEY` and `GOOGLE_AI_API_KEY` are left alone for the same reason; `test_unknown_env_vars_are_ignored` pins that all three are inert.

### 3. The interface

```python
class LLMProvider(ABC):
    @abstractmethod
    async def complete_structured(
        self, system: str, user: str, schema: dict, *,
        label: str = "llm", model: str | None = None,
        max_tokens: int | None = None, effort: str | None = None,
    ) -> LLMResult: ...
```

The three positional arguments are the plan row's. The keyword-only four are an extension: `label` names the call in the log and becomes `json_schema.name`, the rest let 4.2 send the classifier to a different model without a second provider.

`LLMResult` is a frozen dataclass: `data: dict`, `model: str`, `finish_reason: str | None`, `duration_ms: int`, `usage: dict` (camelCase `input`, `output`, `cacheRead`, `cacheWrite`, `reasoning`, `cost`; **every key absent-safe**). It holds no SDK object — the response is parsed and dropped inside the call (G8). `fallback_used` is gone with the fallbacks (decision 9); `finish_reason` is the OpenAI-compatible name and is a new field on a new dataclass, not a rename of anything that ships today.

**Errors** (`base.py`), all under `LLMError` — **renamed nothing**:

| error | meaning | who raises it |
|---|---|---|
| `LLMNotConfigured` | no key | pre-flight step 2 |
| `LLMAuthFailed` | 401 / 402 / 403 (subclass of `LLMNotConfigured`) | post-call |
| `LLMCapExceeded` | the daily cap | pre-flight step 5 |
| `LLMCooledDown` | a refusal inside the cooldown window | pre-flight step 3 |
| `LLMRateLimited` | this call got the 429 | post-call |
| `LLMRejected` | other 4xx — our request is wrong | post-call |
| `LLMUnavailable` | 408, 5xx, transport, timeout, or a 200 carrying an `error` body | post-call |
| `LLMRefused` | `message.refusal` is not null | post-call |
| `LLMBadResponse` | `length`, an unexpected `finish_reason`, not JSON, not an object, missing a required key | post-call |

Every message carries a status code, a key name or an exception **type** — never a URL, never a body, never the key. Typed errors are raised `from None`, the `alphavantage_client` / `fred_client` rule (G14).

4.2 onwards maps them to HTTP: `LLMCapExceeded` / `LLMCooledDown` / `LLMRateLimited` → **429**, which is exactly what risk-shield's `ai_agent_client` already expects from us (spec 3.6b decision 1).

### 4. The daily cap

- **Key:** `tf:ai:state:llm_calls:{YYYY-MM-DD}`, the date in **America/New_York**. Every other daily boundary in this repo is ET (the scheduler's sessions, 3.6b's slots); a UTC day would reset the cap at 20:00 ET, mid after-hours.
- **TTL:** `EXPIRE <key> 129600 NX` — 36 h, set **only if the key has no TTL** (`NX`), so a later call in the same day cannot push the expiry forward. Redis ≥ 7.0 is required for `NX`; prod runs **7.4.11** (V13), and `redis-py 5.3.0` exposes it as `r.expire(key, 129600, nx=True)`.
- **Reserve then call:** `INCR` returns the new count. Over the cap → `DECR` and raise `LLMCapExceeded`. Under → send. `INCR`/`DECR` are atomic, so two concurrent calls cannot both slip past the last slot.
- **A request that went out counts**, whatever it answered. The cap bounds *calls made*; releasing failures is what turns a cap into a retry budget.
- **Redis down → the in-process counter** (`MemoryCap`, keyed by the same ET day), with one WARNING. `release_call` mirrors `reserve_call`, fallback included, so a Redis outage cannot leave the memory counter permanently high.
- **`cap = 0` refuses everything**, which is how the twin is nailed shut without relying on the empty key alone.

### 5. The request

```python
client = AsyncOpenAI(            # built lazily, after pre-flight step 2 (fix A)
    base_url=settings.llm_base_url,
    api_key=settings.llm_api_key.get_secret_value(),
    max_retries=0,
    timeout=settings.llm_timeout,
    http_client=http_client,     # None in prod; httpx2.MockTransport in tests
)

await client.chat.completions.create(
    model=model,
    max_tokens=max_tokens,
    messages=[{"role": "system", "content": system},
              {"role": "user",   "content": user}],
    response_format={"type": "json_schema",
                     "json_schema": {"name": label, "schema": schema, "strict": True}},
    extra_body={"reasoning": {"effort": effort}},   # omitted entirely for a model with none
    extra_headers=headers_or_omitted,               # only when llm_referer / llm_title are set
)
```

Every element of that body was observed on the wire in the offline probe (V8) and is asserted by `test_request_shape_on_the_wire`.

- **Client:** `max_retries=0` is the G6 rule in one argument — the SDK's default of 2 retries a 429 twice before we ever see it. `timeout` is the hard per-call bound. `http_client` is the injection seam (fix A): the tests pass an `httpx2.AsyncClient` wrapping an `httpx2.MockTransport`, so no test constructs an `AsyncOpenAI` itself and nothing is patched.
- **`max_tokens`, not `max_completion_tokens`:** `z-ai/glm-5.3-flash` lists only `max_tokens` in `supported_parameters`; the Anthropic ids list both. One field works for all.
- **Structured output:** the `response_format` / `json_schema` / `strict: true` form, with `name` = the call's `label` (which is why `label` is validated). Confirmed supported for all three ids (V9). Because enforcement "is not guaranteed on every endpoint", the provider **still** checks the answer itself: JSON, object, every `schema["required"]` key present. That check is the reason `strict` is a belt and not the braces — and the reason a schema with an empty `required` is a `ValueError` (fix C).
- **`extra_body`, not a named kwarg:** `reasoning` is an OpenRouter extension. The SDK has a `reasoning_effort` kwarg, but it is OpenAI's flat form, and OpenRouter's documented field is the nested `reasoning` object — the *only* way to enable reasoning on Anthropic models. `extra_body` puts it at the top level of the JSON body verbatim (V8).
- **No `usage: {"include": true}`.** It is deprecated and has no effect (V12); usage is always returned. `cost` is read off the response instead.
- **No streaming**, no tools, no `temperature` — the schema is the contract.

**`MODEL_REASONING`** in `openai_compat_provider.py`, pinned by `test_model_reasoning_pinned_to_spec`. Every row comes from the models API's `reasoning` object (V11), not from memory. `None` means "send no `reasoning` field":

| model id | what the provider sends | why |
|---|---|---|
| `z-ai/glm-5.3-flash` | `{"reasoning": {"effort": "low"}}`, efforts `max/high/low`, mandatory | `default_effort: "max"`; `"low"` is the cheapest accepted value, and `"none"` is rejected by a mandatory model |
| `z-ai/glm-5.3` | identical | identical metadata |
| `anthropic/claude-sonnet-5` | `{"reasoning": {"effort": "low"}}`, efforts `max/xhigh/high/medium/low` | a deliberate down-shift from its `"high"` default |
| `anthropic/claude-haiku-4.5` | **nothing** (`None`) | its `reasoning` object is `{"mandatory": false}` — no `supported_efforts` — and `reasoning_effort` is absent from its `supported_parameters` (V11) |
| anything else | **nothing**, plus one WARNING naming the id | an id that answers without reasoning is recoverable; a 400 on every call is not |

A caller's `effort=` must be in that row's `supported_efforts` or it is a `ValueError` at step 1 (fix B). For a row of `None`, a caller's `effort=` is ignored with one WARNING — sending it is the failure the table exists to prevent.

### 6. The response

In order:

1. **No choices** → if `model_extra["error"]` is an object, `LLMUnavailable` with `status` from `error.code` (fix J); otherwise `LLMBadResponse("no choices")`. OpenRouter sends `200 OK` as soon as a provider accepts the request, so every later failure arrives in the body, and the SDK does not raise on it — `choices` is simply `None` (V8b).
2. `finish_reason == "length"` → `LLMBadResponse("length")`, **before** anything is parsed. A truncated answer is never valid JSON and the error should say why; OpenRouter documents this as exactly the shape a reasoning model takes when it spends the whole budget on reasoning.
3. `message.refusal` is not null → `LLMRefused`, carrying the refusal's **length in characters**, never its text. Checked before step 4 so a content filter that also sets a refusal reads as a refusal rather than as an odd `finish_reason`.
4. Any `finish_reason` other than `stop` or `None` → `LLMBadResponse` naming the reason (fix K).
5. `message.content` → non-blank string → `json.loads` → must be a `dict` → every name in `schema["required"]` must be present. Anything else → `LLMBadResponse`.

**The usage log**, one INFO line per completed call:

```
llm call label=verdict model=anthropic/claude-sonnet-5 in=1204 out=187 cacheRead=1100 cacheWrite=0 reasoning=142 cost=0.00142 finish=stop ms=8412 callsToday=17/100
```

The numbers come from `usage.model_dump()`, which carries OpenRouter's extras (`cost`, `prompt_tokens_details.cache_write_tokens`) alongside the standard fields. Every field is **omitted, not printed as `None`**, when the gateway does not report it. Never the prompt, never the response, never the key (G14).

**The error log**, exactly one WARNING per raised error, same field order, nothing else:

```
llm error label=verdict model=anthropic/claude-sonnet-5 err=LLMRateLimited status=429 ms=812 callsToday=18/100
```

`status=-` when there is no integer status (transport error, timeout, bad response, pre-flight refusal); `callsToday=-/100` when the error was raised before the reservation. No body, no URL, no key. `test_one_warning_line_per_raised_error` asserts the count **and** that the field set is exactly `{label, model, err, status, ms, callsToday}`.

### 7. Testing: `httpx2.MockTransport`, and only that

**`respx` cannot be used here.** The `openai` SDK runs on `httpx2` (a separate distribution, 2.13.0), and `respx` — both 0.22.0 and the current 0.23.1 — requires and patches `httpx` 0.2x (V2, V4, V5). It would install fine and silently intercept nothing.

**One approach, used everywhere in `tests/test_openai_compat_provider.py`:** a `Wire` callable captures the outgoing `httpx2.Request` and returns a canned `httpx2.Response`; it is handed to the provider as `http_client=httpx2.AsyncClient(transport=httpx2.MockTransport(wire))`. That exercises the **real** SDK request builder and the **real** response parser — including the SDK's own status→exception mapping, which is what the 4xx/5xx branches assert. No socket is opened, and the suite runs green under `docker run --network none`.

Consequences, stated so nothing drifts:
- `services/ai-agent/requirements-dev.txt` **omits `respx`**, breaking the "pins match the other two twins exactly" rule for that one line. The file says why in a comment. The other three pins match.
- `httpx2` is not pinned directly — it arrives as `openai`'s dependency, and `pip check` is clean (V3). Pinning a transitive HTTP stack we do not import in application code would be a pin to maintain for nothing.
- `test_sdk_accepts_request_kwargs` uses `inspect.signature(AsyncCompletions.create)` and asserts every kwarg the provider sends is a real parameter. It builds no client and opens nothing. It is the test that catches an `openai` bump that renames a parameter.
- These tests run **inside `tf-ai-agent-dev`**, whose environment hard-codes `SERVICE_NAME`, `LLM_BASE_URL` and `LLM_DAILY_CALL_CAP`. `_env_file=None` disables the dotenv file, not the process environment, so the harness sets every knob a wire assertion depends on explicitly, and `test_defaults_match_spec` reads `Settings.model_fields[...].default` rather than a constructed object.
