## Spec

Part 4.8b gives the verdict model **reads computed in code instead of by the model**, rewrites the rules the verdict prompt enforces, and cuts the classifier's cost. **data-engine** computes four new measurement blocks on the stored daily bars in the indicator snapshot: `volumeRead` (up-day vs down-day RVOL, the last breakout bar, the current pullback), `trendRead` (the price / EMA stack, the EMA20 slope, the last two swing lows), `momentumRead` (`move30Atr`, `range30Atr`, `closesBelowEma20`, `lowerHighs`) and `rangeRead` (the 60-bar range, the position in it, EMA20 crosses); it tags each dossier headline whose title overlaps a stored headline older than 14 days (`rehashOf`); and its sentiment contract accepts the classifier's new `eventDate`. **ai-agent** turns those numbers into `reads`: an `uptrend` yes / no with its four reasons, and six flags (`lowVolumeBreakout`, `distribution`, `dryPullback`, `dead`, `bleeding`, `rangeBound`) at the starting lines of this spec, none of them a hard rule. The verdict prompt makes the model cite every raised flag, name what it waits for on a valid plan, keep numbers out of `invalidation`, and read each event's `ageDays` / `stale` / `rehash` / `sourceType`. Headlines are pre-filtered in code to 15 before the classifier; `oneLine` is capped shorter; the classifier's system prompt is cached; the verdict uses **one** response schema; and a paid Haiku-vs-Sonnet test runs on three tickers. It must **not**: make any read or flag a hard rule (no flag rejects a plan, changes a level, removes `go` from anything, or changes `grading/plan_math.py`; `PLAN_MATH_VERSION` stays 3); let the model supply a number (`test_llm_schema_has_no_number_the_model_could_set` stands, with the new text fields); use `rsSpy5` in any rule; build the swing-low stop rule, the tie rule, the small from-above samples, a target cap change, or the replay part (journal-review list, decisions 2026-09-25); add a migration (every new value lives in `prompt_inputs`, `plan_proposed` or `news_items.sentiment`); write outside `ai` / `tf:ai:` (ai-agent) or `data_engine` / `tf:cache:` (data-engine); switch the prod classifier model, set `LLM_CLASSIFIER_CACHE=true` in prod, or run any paid call inside verification. **Acceptance:** both twins green, 0 skipped, every failure-branch test below passing by name; the momentum fixtures reproduce X1's eleven rows to the digit and the other reads reproduce decision 5's table; `PROJECTION_VERSION` 5 with the pin literal updated and both indicator pin tests updated; a twin round trip storing one verdict whose `prompt_inputs` carries the four read blocks, `reads` and `readsVersion`, and whose request used the single schema; the cost table (decision 13) filled with **measured** after-figures from the paid steps, each run on Zubair's own word, before 4.8b is closed.

## Decisions

### 1. Where each piece lives

Measurements from bars live in **data-engine** (the bars are there; ai-agent never reads another service's schema). Thresholds and flags live in **ai-agent** (`reads.py`, pure, new), so a starting line can be retuned without a data-engine rebuild, and they carry their own version: **`READS_VERSION = 1`**, in the cache fingerprint and stored as `prompt_inputs.readsVersion`. Bump it on any threshold or flag-rule change, the same rule as `PLAN_MATH_VERSION`. A flag change without a bump mixes eras in the journal. `test_reads_version_in_fingerprint`, `test_reads_version_is_pinned` (the constants pinned with it).

### 2. `volumeRead` (data-engine, item 1)

On the stored daily bars, with `rvol(k) = volume[k] ÷ mean(volume[k−20 … k−1])` (`calc_rvol`'s convention, X3, as a series; NaN under 21 bars):

- **RVOL today** is the existing `rvol` (projected `rvol`); it is not repeated.
- **`upDays5Rvol` / `downDays5Rvol`**: the mean `rvol` of the last 5 up closes (close > previous close) and the last 5 down closes, looked for inside the last 60 bars. Null when fewer than 5 are found. Flat closes count as neither.
- **`breakout`**: the newest bar among the last 5 whose close cleared a zone, meaning `previous close ≤ zone.high < close` for any zone in the snapshot's `zones` (support or resistance; a zone price has cleared is listed as support by now) **that has held from below at least as often as it broke (`heldBelow ≥ brokeBelow`)** *(approval, answer 1)*. Emits `{date, low, high, barRvol}` (the zone's band, the bar's `rvol`) or null. Only the newest breakout is emitted.
- **`pullbackDays` / `pullbackRvol`**: the run of consecutive down closes ending at the last bar and the mean `rvol` over it; 0 / null when the last close is not down.

Keys (camelCase out, snake_case in Python, aliased like every other field): `volumeRead: {upDays5Rvol, downDays5Rvol, breakout: {date, low, high, barRvol} | null, pullbackDays, pullbackRvol}`. `Rvol` and `Days` join `UNIT_SUFFIXES` (a multiple of the 20-bar average volume; a count of trading days), and the prompt's units sentence names both. `test_volume_read_up_down_days`, `test_volume_read_breakout_newest_in_last_five`, `test_volume_read_no_breakout`, `test_volume_read_pullback_run`, `test_volume_read_short_history_nulls`.

### 4. `rangeRead` (data-engine, item 4)

The range is the **60 bars before the last bar**, so the last bar can be outside it: `low` = min low, `high` = max high over those 60; `posFrac = (close − low) ÷ (high − low)` (below 0 or above 1 when the last close is outside); `closedOutside` = last close > `high` or < `low`; `ema20Crosses40` = sign changes of `close − ema20` between consecutive bars over the last 41 bars (40 transitions; a zero difference breaks no run and makes no cross). Keys `rangeRead: {low, high, posFrac, ema20Crosses40, closedOutside}`; `low` / `high` are declared price levels already. Null under 61 bars. `test_range_read_position_and_crosses`, `test_range_read_last_bar_outside`, `test_range_read_short_history`.

### 5. `reads` and the six flags (ai-agent, items 1–5)

`reads.build(indicators, *, today, now) → dict`, pure, called in `analyze.project` and stored under `prompt_inputs.reads`:

- **`uptrend`**: true only when all four checks hold; **`trendReasons`**: four short fixed strings, one per check, each with its value and ✓ / ✗ (for example `"close 338.98 > EMA20 326.33 > EMA50 318.43 ✓"`, `"RS 20d vs SPY unknown ✗"`); null RS is a failed check, never a pass.
- **Flags, at these starting lines (provisional, `READS_VERSION` 1):**

| flag | fires when | reading |
|---|---|---|
| `lowVolumeBreakout` | `breakout` present and `breakout.barRvol < 1.0` | caution |
| `distribution` | `downDays5Rvol > 1.5 × upDays5Rvol` | caution |
| `dryPullback` | `pullbackDays ≥ 2` and `pullbackRvol < 0.7` | positive |
| `dead` | `abs(move30Atr) < 1.5` and `range30Atr < 5` | caution |
| `bleeding` | `move30Atr ≤ −1.5` and `closesBelowEma20 ≥ 10` and `lowerHighs` | caution |
| `rangeBound` | `0.2 ≤ posFrac ≤ 0.8` and `ema20Crosses40 ≥ 5` and not `closedOutside` | caution |

- **Partial bar:** when the dossier's `asOf` date is today's XNYS session and `now` is before that session's close (`journal.sessions`, already in ai-agent, early closes included), the last bar is partial (X4). The three volume flags are then **withheld**, listed in `reads.withheld` with the reason `partial bar`, because each can read that bar. The other three read closes and ranges and stay, with `reads.lastBarPartial: true` so the model knows.
- A flag whose input is null is neither raised nor withheld; it is absent. `reads.flags` lists the raised names in the table's order.

### 7. The verdict prompt (items 5, 6)

- **Legend** for the four blocks and `reads`: what each flag means, that flags are starting lines and **not rules**, that `withheld` flags read a partial bar and are unknown, not false.
- **"Every flag in `reads.flags` is named, by its name, in `reasoning`, with what it means for this setup."** Checked in code (decision 9).
- **Wait on a valid plan names a breaker:** when `plan` is present and the verdict is `wait`, the new field **`waitFor`** says the one thing that blocks `go` now and the observable condition that would clear it (a flag clearing, `entryForMaxRisk`, an event, a regime change). Empty string otherwise. Stored inside `plan_proposed` (no migration). Open question 2 offers the prompt-only form instead.

### 8. One response schema (item 8, X11)

`llm_schema()` takes no arguments and returns one schema for every call: the verdict enum is always `go / wait / avoid`, and the plan fields (`invalidation`, `holdThroughEarnings`, `horizonDays`, `waitFor`) are always present and nullable. One prefix per `prompt_sha` instead of three. **The cost:** the decoder no longer makes `go` impossible without a plan or on an extended plan (4.4, 4.8a-de decision 6). `merge` already rejects both (`go without a plan`, `go on an extended plan`); from now on it also rejects a non-null plan field on a no-plan answer, and a null plan field on a plan answer. The prompt carries the rules in words, and the first paid calls show whether a model breaks them. `test_llm_schema_is_one_schema`, `test_merge_refuses_go_without_plan` (new name for the assertion in `test_verdict_prompt.py:432`), `test_merge_refuses_go_on_extended_plan` (kept), `test_merge_refuses_plan_fields_without_plan`, `test_merge_refuses_null_plan_fields_with_plan`, `test_llm_schema_has_no_number_the_model_could_set` (kept: `waitFor` is text).

### 9. Soft checks, never a rejection

`merge` checks three rules that a paid answer should not be thrown away over, and reports them without repairing anything: an uncited flag (the flag name, case-insensitive, is not a word in `reasoning`), a number in `invalidation` (`\$?\d+\.\d+` or `\$\d+`; "20 EMA" passes), and a blank `waitFor` on `wait` + plan. Each produces a string in `contractWarnings`, logged at WARNING, returned in the `/analyze` response and stored in `plan_proposed.contractWarnings` when a plan exists (no column, no migration). ### 10. Rehash: three layers (item 7)

- **Layer 1, token overlap (data-engine):** `news_tokens(title)`, the one normalization function (G1.5): lowercase, split on non-alphanumerics, drop a fixed stopword list, tokens of 1–2 characters and the ticker itself. In `build_news`, one read (`db.get_news_titles(pool, ticker, older_than=today − 14 d, since=today − 180 d)`); a kept headline whose token set has Jaccard ≥ **0.5** with a stored title, and at least 4 shared tokens, carries `rehashOf: {id, publishedAt, overlapFrac}` (the best match). Starting lines, provisional. The build reports how many of the 1,056 stored rows match an older stored row by this rule (read-only). `test_news_tokens_normalization`, `test_rehash_of_marks_overlap`, `test_rehash_of_ignores_recent_rows`, `test_rehash_of_below_threshold`, `test_rehash_lookup_db_failure_is_503` (a raise in the read is a DB failure like `get_news_labels`', X6).
- **Layer 2, source type (ai-agent, code, no LLM):** `sources.source_type(source, title, summary) → "analyst" | "news"`. `analyst` when `source` is `SeekingAlpha` or `ChartMill` (X7), or the title or summary matches `\bzacks\b`, `\bmotley fool\b`, `\bfool\.com\b` (case-insensitive): Zacks and Motley Fool arrive as `Yahoo` (X7), so a source-name map alone would never see them. ChartMill is this spec's addition (technical-analysis commentary): open question 4. An `analyst` event's relevance is **capped at `medium`** unless it carries a new fact (below). `test_source_type_map`, `test_source_type_catches_syndicated_zacks`, `test_analyst_relevance_capped_at_medium`.
- **Layer 3, `eventDate` (classifier):** a new required item field, an ISO date or null: the date the event itself happened or is scheduled, **only when the headline or summary states it**; null otherwise (never inferred). Validated as `YYYY-MM-DD` or null, rejected whole otherwise (the batch rule). A **new fact** = `eventDate` not null and on or after `publishedAt − 3 days` (a future date counts). The contract grows on both sides: `ITEM_LIMITS["eventDate"]` and data-engine's `NewsSentimentRequest.eventDate` (optional there), both pin tests naming the other side. **Labels cached before this part** have no `eventDate` and are served as `null`, not re-classified (X15: re-classifying would pay for every cached label again). `test_event_date_validated`, `test_event_date_optional_in_sentiment_contract` (data-engine), `test_item_limits_pinned_to_spec` (updated), `test_sentiment_contract_pinned_to_spec` (updated), `test_cached_label_without_event_date_is_served`.
- **In `events.group`:** an event is `rehash` when any member carries `rehashOf` or its `eventDate` is more than 14 days before its `firstSeen`; `stale` when `ageDays > 14`. ### 15. The open session's bar is never stored (4.8b-de, approval addition a)

### 16. `sessionSoFar` (4.8b-de, approval addition b)

When a write path drops today's daily row (decision 15), it computes from the same download `{open, high, low, last, volumeSoFar, sessionElapsedFrac, changeVsPriorClosePct, rvolScaled, inProgress: true}` and keeps it in Redis (`tf:cache:session:{ticker}`, TTL = seconds to the session's close): `sessionElapsedFrac` = time since the open over the session's real length at the download instant; `changeVsPriorClosePct` against the last closed daily bar; `rvolScaled` = `volumeSoFar ÷ sessionElapsedFrac ÷ mean(volume of the 20 prior sessions)`, null in the first 5 minutes. `IndicatorsResponse` gains `session_so_far` (alias `sessionSoFar`), attached **at read time** to `/indicators/{t}` and to the dossier's indicators section, never stored in either cache body: null when no session is open at read time (so a body cached at 15:55 cannot carry it past 16:00) or when no stash exists. **The block exists only when a refresh or scan downloaded this session**: the dossier does not download for it (its stale rule refreshes only when bars are more than a weekday behind). `volumeSoFar` is shares and `rvolScaled` a ratio like `rvol`: 4.8b-ai declares both on the ai-agent side. Added to the data-engine pin test. `test_session_so_far_block`, `test_session_so_far_null_after_close`, `test_session_so_far_not_in_cached_body`, `test_session_so_far_absent_without_stash`.
