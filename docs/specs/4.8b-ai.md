## Spec

Part 4.8b-ai turns data-engine's four read blocks into **`reads`** (`reads.py`, pure: `uptrend` with its four reasons and the six flags `lowVolumeBreakout`, `distribution`, `dryPullback`, `dead`, `bleeding`, `rangeBound` at the parent spec's starting lines, under `READS_VERSION` 1), projects the four blocks and **`sessionSoFar`** into the verdict document with their units and puts a `sessionSoFar` price bucket and `READS_VERSION` into the cache fingerprint (`PROJECTION_VERSION` 5), gives every event `ageDays` / `stale` / `rehash` / `sourceType` / `eventDate` with the analyst and rehash relevance caps, pre-filters headlines to 15 in code before the classifier, asks the classifier for `eventDate` and a 120-character `oneLine` behind an optional cached system prompt (`LLM_CLASSIFIER_CACHE`, default off), moves the verdict to **one** response schema with `waitFor` and three soft `contractWarnings`, rewrites the verdict prompt's legend and rules accordingly, and adds the Haiku-vs-Sonnet knob script. It must **not**: let any read or flag reject a plan, change a level or remove `go` (no flag is a rule; `grading/plan_math.py` is not edited and `PLAN_MATH_VERSION` stays 3); let the model supply a number (`test_llm_schema_has_no_number_the_model_could_set` stands; `waitFor` is text); read `sessionSoFar` in any flag or in plan math; use `rsSpy5` in any rule; add a migration (`readsVersion`, `reads`, the blocks live in `prompt_inputs`; `waitFor` and `contractWarnings` in `plan_proposed`; `eventDate` in `news_items.sentiment` through the existing write-back); touch data-engine or any schema but `ai` / `tf:ai:`; change the prod `.env`, switch the prod classifier model, or make any paid call, prod rebuild or tag inside the build. **Acceptance:** the ai-agent twin green, 0 skipped, every failure-branch test below passing by name; `test_flags_on_the_eleven` reproducing decision 2's table from the committed fixture (5 / 11 breakouts, `lowVolumeBreakout` on AAL only); `PROJECTION_VERSION` 5 with the pin literal updated and the report stating the path count against it; `test_session_so_far_in_fingerprint` and `test_reads_version_in_fingerprint` passing; a twin round trip storing one verdict whose `prompt_inputs` carries `reads`, `readsVersion` 1, `projectionVersion` 5, the four blocks and `sessionSoFar` under `indicators`, whose `plan_proposed` carries `waitFor` and `contractWarnings`, and whose request used the single schema; the report in 4.8b-de's format (decision 15); commits under 600 changed lines each, measured before push; the deploy and paid steps listed and waiting, each for its own "go <n>".

## Decisions

### 1. `reads.py`: `READS_VERSION` 1, the thresholds in one place

`reads.build(indicators, *, today, now) -> dict`, pure, over data-engine's raw indicator section (the dossier's keys, before projection: `trendRead`, `rsSpy20`, …). Every starting line is a module constant, and `THRESHOLDS` is the tuple of all of them:

| constant | value | flag |
|---|---|---|
| `LOW_VOLUME_BREAKOUT_RVOL` | 1.0 | `lowVolumeBreakout`: `breakout` present and `breakout.barRvol < 1.0` |
| `DISTRIBUTION_RATIO` | 1.5 | `distribution`: `downDays5Rvol > 1.5 × upDays5Rvol` |
| `DRY_PULLBACK_DAYS`, `DRY_PULLBACK_RVOL` | 2, 0.7 | `dryPullback`: `pullbackDays ≥ 2` and `pullbackRvol < 0.7` |
| `DEAD_MOVE_ATR`, `DEAD_RANGE_ATR` | 1.5, 5 | `dead`: `abs(move30Atr) < 1.5` and `range30Atr < 5` |
| `BLEEDING_MOVE_ATR`, `BLEEDING_CLOSES_BELOW` | −1.5, 10 | `bleeding`: `move30Atr ≤ −1.5` and `closesBelowEma20 ≥ 10` and `lowerHighs` |
| `RANGE_POS_LOW`, `RANGE_POS_HIGH`, `RANGE_CROSSES` | 0.2, 0.8, 5 | `rangeBound`: `0.2 ≤ posFrac ≤ 0.8` and `ema20Crosses40 ≥ 5` and not `closedOutside` |

- **`uptrend`** is true only when all four hold: `trendRead.stackUp`, `trendRead.ema20Rising10`, `rsSpy20 > 0` (null is a failed check, never a pass), `trendRead.higherLows`. **`trendReasons`** are four fixed strings in that order, each with its values and `✓` / `✗` (`"close 338.98 > EMA20 326.33 > EMA50 318.43 ✓"`, `"EMA20 rising over 10 bars ✓ (+0.41 ATR)"`, `"RS 20d vs SPY unknown ✗"`, `"higher swing lows ✗ (35.30 → 34.10)"`). `rsSpy5` is never read (`test_uptrend_ignores_rs_spy_5`).
- **Output:** `{uptrend, trendReasons[4], flags[], withheld[], lastBarPartial}`; `flags` lists the raised names in the table's order. A flag whose input is null (an old cached dossier, a short history) is neither raised nor withheld: absent (`test_flag_absent_when_input_null`). Inputs are never mutated and the same inputs give the same output (`test_reads_deterministic_and_pure`).
- **`READS_VERSION = 1`**, in the fingerprint (decision 6) and stored as `prompt_inputs.readsVersion`. Bump it on any change to a constant above or to a flag rule, the `PLAN_MATH_VERSION` rule. `test_reads_version_is_pinned` pins `(READS_VERSION, THRESHOLDS)` to their literals, so a line cannot move without the bump. `test_flag_boundaries` takes each line at, just under and just over. `test_uptrend_needs_all_four`, `test_uptrend_null_rs_fails`.

### 5. `sessionSoFar`: projected, in the fingerprint, read by nothing else (items 1, 2)

- **Projected** as-is under `indicators.sessionSoFar` (null outside market hours or without a stash, as data-engine sends it). No flag, no reason string and no plan-math input reads it (`test_reads_ignore_session_so_far`).
- **Legend** in `prompts/verdict.md`: *`sessionSoFar` is today in progress, not a candle: `last` is the latest trade, `volumeSoFarShares` the shares so far, `sessionElapsedFrac` how much of the session has run, `scaledRvol` that volume scaled to a full session over the 20-session mean. Every plan level, every read and every flag comes from closed bars, and `asOf` is still the last closed bar. `null` means no session view was available (outside market hours, or nothing fetched yet); it says nothing about today's move.* `test_prompt_names_session_so_far_legend`.
- **Fingerprint:** `sessionBucket = price_bucket(sessionSoFar.last, reference_entry, atr14)` when the block is present, else `None`, beside `priceBucket` (which stays on the closed bar). So a ≥ 1 ATR move since the verdict's entry retires the cache during the session (what X3 lost), a 15-minute refetch that moved less keeps it, and the open / close boundary retires it once (null ↔ a number). *(approval)* `reference_entry` is the entry the cached verdict was given for: with no `entry` passed it is the dossier's last daily close in cents (`analyze.resolve_entry`, `analyze.py:109–115`, `ENTRY_LAST_CLOSE`), and the cache compares against the held entry (`analyst.py:216`, `fingerprint_from(held["entry"])`) while the stored fingerprint uses the resolved one (`analyst.py:284`). `test_session_so_far_in_fingerprint` has **four cases**: absent → present invalidates; `last` ≥ 1 ATR from the entry invalidates; two `last` values inside the same whole-ATR bucket, with a new `volumeSoFarShares` and `sessionElapsedFrac`, are served; a move under 1 ATR that crosses a bucket edge (0.99 → 1.01 ATR) retires the entry. **The alternative** is the whole block in the basis, which retires the cache on every refetch (≤ every 15 min) and makes a repeat analyze in market hours a paid verdict each time; it is not recommended (open question 1; *(approval)* the bucket).

### 8. One response schema (parent decision 8, answer 3)

`analyze.llm_schema()` takes no arguments: `verdict` is always `["go", "wait", "avoid"]`; `invalidation` (string | null), `holdThroughEarnings` (boolean | null), `horizonDays` (integer | null) and **`waitFor`** (string | null) are always present and nullable; every field required, no additional properties, **no numeric field the model could set** (`waitFor` is text). One cached prefix per `prompt_sha` instead of three (parent X11). What the decoder no longer forbids, `merge` rejects whole, the paid answer discarded (the contract rule): `go` without a plan; `go` on an extended plan; a non-null `invalidation` / `holdThroughEarnings` / `horizonDays` on a no-plan answer (a blank string counts as null); a null one of those three on a plan answer. *(approval)* **`waitFor` is accepted on any answer, with or without a plan:** on a plan answer it is stored in `plan_proposed.waitFor`; on a no-plan answer a non-null `waitFor` is not a rejection — it is returned on the response (`waitFor` top-level) and logged, not stored. Null or blank on a verdict that is not `wait`; on `wait` a blank one is a soft warning (decision 9), never a rejection. Cap **300** characters, trimmed like `invalidation`. `models.verdict.Plan` gains `wait_for: Optional[str]` (alias `waitFor`, default None, so every stored row still parses). `test_llm_schema_is_one_schema`, `test_merge_refuses_go_without_plan` (the assertion at `test_verdict_prompt.py:432`, named), `test_merge_refuses_go_on_extended_plan` (kept), `test_merge_refuses_plan_fields_without_plan` (the three fields, not `waitFor`), `test_merge_refuses_null_plan_fields_with_plan`, `test_llm_schema_has_no_number_the_model_could_set` (kept, `waitFor` covered), `test_wait_for_is_stored_in_plan_proposed`, `test_wait_for_allowed_without_plan_not_stored`. The stub provider in `test_analyze.py` stops emulating the decoder (X8).

### 9. Soft checks: `contractWarnings` (parent decision 9)

`analyze.soft_checks(verdict, raised_flags) -> list[str]`, pure, called by `merge` after validation; `merge` returns `(Verdict, warnings)`. Four checks *(approval: the fourth)*, none repairs or rejects: **uncited flag** — a name in `reads.flags` that is not a whole word, case-insensitive, in `reasoning` (`"flag lowVolumeBreakout not cited in reasoning"`); **number in `invalidation`** — `\$?\d+\.\d+` or `\$\d+` (`"20 EMA"`, `"RSI 40"` pass; `"13.33"`, `"$13"` warn); **blank `waitFor`** on `wait` with a plan; **a level in `waitFor` that is nobody's** — a number in `waitFor` matching the same regex that equals no level in the plan (entry, stop, disaster line, `entryForMaxRisk`, every target and overhead price) or in the zone list (each zone's `low`, `high`, `price`), compared to the cent → `"waitFor level 45.76 not in plan or zones"`; a number that matches one passes. Each warning is logged at WARNING, returned as `contractWarnings` on the `/analyze` response (an empty list when there is none, on cached answers the stored list), and stored in `plan_proposed.contractWarnings` when a plan exists (`Plan.contract_warnings: list[str]`, default empty; no column). Without a plan the warnings are returned and logged, not stored. `test_uncited_flag_warns_not_rejects`, `test_price_in_invalidation_warns`, `test_ema_period_in_invalidation_passes`, `test_blank_wait_for_warns`, `test_wait_for_level_not_in_plan_warns`, `test_wait_for_level_from_plan_passes`, `test_contract_warnings_stored_and_returned`.

### 10. `sources.py`: the source type (parent decision 10 layer 2, answer 4)

### 11. Events: age, stale, rehash, source type, the caps, the pre-filter (parent decisions 10 layer 3 and 11, answers 5)

- **`events.group`** gains per event: `eventDate` (the lead label's, else the first non-null among the members' labels, else null), `ageDays` (`today − eventDate`, else `today − firstSeen.date()`; null when neither exists; negative = scheduled ahead; `group` gains `today`), `stale` (`ageDays > 14`), `rehash` (any member carries a `rehashOf` dict, or `eventDate` is more than 14 days before `firstSeen`), `sourceType` (`analyst` only when every member is `analyst`, else `news`). `event_age_days(event_date, first_seen, today)` is the one function for the age.
